# 00 · 图片规范、命名与存储

## 一、六类图片

| 槽位 | 目录 | 比例 | 目的 | 硬要求 |
| --- | --- | --- | --- | --- |
| 图1 身份标准照 | `01_identity/` | 3:4 / 4:5 | 锁脸 | 正面胸像、正对镜头、双眼直视、头部端正、克制表情、灰/浅灰中性背景、柔和棚光、无剧情无特效、原则上不持武器 |
| 图2 人物设计图 | `02_design/` | 3:4 / 2:3 | 锁身体与造型 | 中间大正面全身 + 左侧小侧面全身 + 右侧小背面全身；同脸同头身比同服装同鞋靴同配饰同武器；仅正面含武器结构；禁止表情九宫格与文字说明 |
| 视频角色资产图 | `03_video_asset/` | 大尺寸 | 图生视频一致性参考 | 1 张大身份胸像 + 正/侧/背 3 个完整全身；背景简单；无剧情、动作、特效、设计板 |
| Hero Key Art | `04_hero_art/` | 2:3 | 一眼说明「他是谁、他最特殊的能力是什么」 | 人物占 55–70%，中景最清晰，前景可虚化制造纵深，后景承担世界观与能力展示；**每张只允许一个核心事件**；先问「什么画面只有这个角色能出现」再构图 |
| 视频 Hero Frame | `05_hero_frame/` | 16:9 | 图生视频起始帧 / 关键帧 | 一个瞬间：起手、冲刺、格挡、召唤、释放、命中、卸力、落地、收招；动作满足「来源 → 运动方向 → 接触点 → 环境反馈」；脸不能被遮挡或糊掉；动作幅度不得违反人体力学 |
| 战斗特效图 | `06_effect/`（按需） | 9:16 | 验证能力视觉 | 必须回答：从哪产生 → 向哪运动 → 接触了什么 → 接触后发生什么；特效必须有材料逻辑；禁止所有属性都变成「彩色光束 + 粒子 + 法阵」 |

> 角色卡 md 中的顺序即上表顺序：`图1｜身份标准照 / 图2｜人物设计图 / 视频角色资产图 / Hero Key Art / 视频 Hero Frame / 战斗特效图`。

## 二、命名规范

```
<拼音ID>_<类型>_v00n.png
```

- `拼音ID`：全角色唯一、全小写、无空格，如 `xinglan`、`beiHanming` → 统一用 `beihanming`。
- `类型`：

| 类型 | 文件名片段 | 说明 |
| --- | --- | --- |
| 身份标准照 | `identity` | `xinglan_identity_v001.png` |
| 人物设计图 | `design` | `xinglan_design_v001.png` |
| 视频角色资产图 | `videoasset` | `xinglan_videoasset_v001.png` |
| Hero Key Art | `hero` | `xinglan_hero_v002.png` |
| 视频 Hero Frame | `frame_<动作>` | `xinglan_frame_dash_v001.png` |
| 战斗特效图 | `effect` | `xinglan_effect_v001.png` |
| 预览图（≤512px） | 同名 + `_preview` | `xinglan_identity_v001_preview.png` |

- **禁止**：`星澜最终.png`、`星澜新.png`、`星澜最新版2.png`。

## 三、版本规则

| 版本 | 含义 |
| --- | --- |
| `v001` | 初版 |
| `v002` | 修正版（构图 / 服装 / 环境调整） |
| `v003` | 定稿（进入锚点，后续只许微调） |
| `v00n+` | 换装 / 换时期：加后缀，如 `v004_dress02` |

同一角色的同一类型**只保留一个「定稿」**，其余保留在 `05_GENERATION_LOG/rejected_designs/` 并写明失败原因。

## 四、存储策略

- Git 内：≤512px 预览图、md、prompt、metadata。
- Git LFS：`*.png / *.jpg / *.psd / *.mp4 / *.mov`（已在 `.gitattributes` 配置），存 4K 图、视频资产、Hero Frame。
- 首次克隆后：`git lfs install && git lfs pull`。
- 4K 原始图另在 Mac「图片集中」有一份实体备份，两边靠命名规范对齐。
